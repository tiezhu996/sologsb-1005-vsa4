# 专利权利要求映射工作台

用于专利代理人与审查人员核对权利要求、技术特征和说明书支持依据的前端工作台。案卷按“冻结案件包 + 复核变更单”分离保管，外部复核只交换变化项，导入时逐项与冻结基线三向比对，冲突进入待决区，确认后才生成可编辑案卷。

## 外部复核工作流

1. **冻结外发**：代理人在“冻结外发”面板冻结当前案卷，得到不可变《冻结案件包》JSON（含权利要求、技术特征、说明书段落与整体基线哈希）。冻结后本机继续录入的特征与支持依据不受回传影响。
2. **离线复核**：
   - 同机可直接“本机直接复核”；
   - 外部电脑通过“导入冻结包开始复核”打开，工作副本与本机案卷完全隔离，说明书段落只读。
3. **回传变更单**：复核结束只导出《复核变更单》，其中仅含按**权利要求 / 技术特征 / 支持映射记录**三类的新增、修改、删除（含各自基线哈希），不交换整份案卷。
4. **导入三向比对**：导入时核验冻结包 id 与整体基线哈希，逐项比对“冻结基线 / 本机现状 / 变更单拟议”：
   - 仅复核端改过、本机未动 → 自动可合入；
   - **原对象已在本机移除**（source-removed）或**两边都改过**（both-changed）等冲突 → 进入**待决区，不直接写入**；
   - 支持段落缺失、同单引用缺失等同样进入待决区。
5. **逐项决议与确认**：离线复核员对每个待决项选择“采纳变更单”或“保留本机”，全部决完后确认合并，才生成可编辑案卷。可一键全部采纳/拒绝，也可对已决项改判；确认前可放弃合并，案卷保持导入前状态。
6. **独立留存**：历次冻结包原件、回传变更单原件、合并会话与全部处理记录（升级、冻结、复核、导入、决议、确认、存储恢复）独立留存，可在“冻结与留存”页查看并重新导出。

### 数据安全

- 持久化采用 v2 信封（`patent-workbench-envelope-v2`），写入流程为：临时键写入 → 回读比对 → 覆盖主键 → 再回读 → 清理临时键。任何一步失败（如配额超限）都不覆盖主键，**上一版完整案卷始终完好**，界面挂出存储故障并可重试。
- 主键损坏但临时键完好时，重开自动用已校验副本恢复完整案卷并留痕。
- 待决合并会话与复核工作副本随信封持久化，**重开页面可接着处理未决项**。
- 检测到 v1 旧整包（`patent-claim-mapping-workbench-v1`）时首次打开**原位升级**为 v2 信封并补建首个冻结基线，升级成功后删除旧键。

## 其它功能

- 录入独立/从属权利要求与说明书段落。
- 将权利要求拆分为技术特征，设置父级层级、特征间引用和负责角色。
- 为每个特征映射一个或多个说明书支持段落。
- 自动提示引用循环、缺少依据、空特征和“特征已删除但映射未清理”；外部合并删除特征时其原映射进入待清理清单。
- 角色切换与批注隔离：代理人、审查员只能修改本人批注，观察者只读；存在待决合并时锁定主数据编辑。
- 案件编辑与复核编辑各自独立的撤销/重做（`Ctrl/⌘ + Z`、`Ctrl/⌘ + Shift + Z`）。
- 保存权利要求版本，逐项比较正文差异并恢复历史版本。
- 导出完整 JSON、可核对的 CSV 与处理记录 JSON，本地保存上次标签页、特征和滚动位置。

## 技术栈

- Angular 19、TypeScript、RxJS
- PrimeNG 19、PrimeIcons
- 浏览器 `localStorage`（原子两键写入）

## 本地开发

```bash
npm install
npm start
```

开发服务器监听容器内端口 4200，仅用于本地开发；项目不在源码中定义宿主端口。

## 生产构建

```bash
npm install
npm run build
```

产物位于 `dist/patent-claim-workbench/browser`。

## Docker

```bash
docker build -t sologsb-1005 .
docker run --rm -p 10005:80 sologsb-1005
```

nginx 在容器 80 端口提供构建产物，并按根端口表映射到宿主 `10005`。
