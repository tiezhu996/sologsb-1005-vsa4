# 专利权利要求映射工作台

用于专利代理人与审查人员核对权利要求、技术特征和说明书支持依据的前端工作台。数据按案件本地保存，可恢复上次工作位置。

## 功能

- 录入独立/从属权利要求与说明书段落。
- 将权利要求拆分为技术特征，设置父级层级、特征间引用和负责角色。
- 为每个特征映射一个或多个说明书支持段落。
- 自动提示引用循环、缺少依据、空特征和“特征已删除但映射未清理”。
- 角色切换与批注隔离：代理人、审查员只能修改本人批注，观察者只读。
- 全量操作撤销重做，使用 `Ctrl/⌘ + Z` 与 `Ctrl/⌘ + Shift + Z`。
- 保存权利要求版本，逐项比较正文差异并恢复历史版本。
- 导出完整 JSON 或可核对的 CSV，本地保存上次标签页、特征和滚动位置。

## 冻结案件包与复核变更单

外部复核不再交换整份文件，避免回传导入时覆盖本机后来录入的内容：

1. **冻结案件包**：在“冻结与复核”页把当前权利要求、技术特征、说明书段落冻结为带校验和的基线包，导出给外部复核员；冻结后本机继续编辑不影响基线。
2. **离线复核**：复核员打开冻结包，在离线复核工作区中按权利要求、技术特征、支持映射逐项修改；草稿双库自动保存，关闭重开可继续，最终只导出**复核变更单**（增量 + 校验和）。
3. **导入逐项比对**：导入变更单时按冻结基线与本机现状做三方比对：
   - 本机未动、外部改动 → 标记“可直接采用”；
   - 外部改动本地已具备 → 标记“冗余”；
   - **原对象已在本机移除** 或 **两边都改过同一对象** → 进入**待决区**，绝不直接写入案卷；
4. **确认合并**：待决项逐项裁决（采用复核方 / 保留本机，可批量）后，复核员确认才生成可编辑案卷，同时自动补建合并后的新冻结基线；确认按钮在存在未裁决项时锁定。
5. **独立留存**：旧冻结包、变更单、含裁决结果的会话与全部处理记录写入独立归档库，不受案卷主库损坏影响。

## 本机存储保障

- 案卷以 v2 结构（可编辑案卷 + 冻结基线 + 会话 + 记录）写入 `localStorage`，整库带校验和；**主库写入前先把上一版完整案卷复制到备份库**，写入失败或回读不一致时自动回滚——磁盘与内存都保住上一版完整案卷。
- 重开应用时：主库损坏则从备份库恢复并原位修复主库；主备皆不可读则给出提示。
- 未决合并会话随案卷持久化，重开后可继续处理未决项。
- **旧版整包数据首次打开时原位升级**为 v2，自动补建首个冻结基线，升级成功后才移除旧键；失败则保留旧数据兜底。

## 技术栈

- Angular 19、TypeScript、RxJS
- PrimeNG 19、PrimeIcons
- 浏览器 `localStorage`（主库 + 备份库 + 独立归档库 + 复核草稿库）

## 本地开发

```bash
npm install
npm start
```

开发服务器监听容器内端口 4200，仅用于本地开发；项目不在源码中定义宿主端口。

## 生产构建

```bash
npm install
npm run build
```

产物位于 `dist/patent-claim-workbench/browser`。

## 逻辑测试

纯 Node + esbuild 的端到端断言（差异生成、三方分类、待决裁决、合并应用、旧数据升级、双库恢复、写失败保住上一版、重开续处未决项）：

```bash
npm test
```

## Docker

```bash
docker build -t sologsb-1005 .
docker run --rm -p 10005:80 sologsb-1005
```

nginx 在容器 80 端口提供构建产物，并按根端口表映射到宿主 `10005`。

## 数据说明

数据与版本存在浏览器本地。若需团队共享或长期归档，请在后续接入后端存储；当前实现为明确的前端离线原型。
